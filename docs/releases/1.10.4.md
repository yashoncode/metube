## Why this release

Three GitHub issues arrived on launch day. Two are fixed here: the phone's font
and display size were ignored outside the feed (#3), and Settings → About →
Check for updates failed with "Value Not of type java.lang.String" (#4). The
third, made-for-kids videos stopping with "Unknown source error" (#5), is
understood but not shipped: the fix works in the engine, and on a real phone its
first media request of each answer is refused for a few seconds, which the
player does not honour yet. Rather than a hotfix, the way NewTube chooses a
YouTube client is being reworked and measured (see Validation).

## Validation and limitations

- Unit tests on the release tree: **633 in `smarttubetv`** (1 opt-in benchmark
  skipped), **258 in `common`**, and **255** player, token, request-builder and
  bot-wall tests in `youtubeapi` passed. The full `youtubeapi` suite ran 610
  tests: its 67 failures are all upstream's live-account integration tests
  (sign-in token, Drive, playlists), which fail the same way without these
  changes.
- Cross-model reviews (Codex `gpt-6-sol`): the update feed (older release could
  roll the feed back; a failed `--clobber` upload could delete it — both fixed)
  and the WEB_EMBED change (a failed embed-page fetch could pair flags with the
  wrong visitor; a WEB_EMBED 403 reset the unrelated web token session — both
  fixed). Not addressed: an x86_64-only device would be offered the universal
  APK, which carries ARM libraries only.
- #4 verified end to end on an ARM Android emulator against the live `latest`
  feed (holding the 1.10.3 manifest).
- #3, emulator measurements (px, default font / 1.3 font / UI scale 1.2): feed
  meta 46 / 61 / 56, tab label 34 / 34 / 41, You row 53 / 68 / 63 (before: 46,
  28, 44 at default). Tablet, player and picture-in-picture layouts checked.
  The reporter said UI scale 1.4 already helped on 1.10.3.
- #5 (not shipped): a Pixel 9 run over LTE and Wi-Fi (package `…arc.check`,
  signed out) showed WEB_EMBED answering but its first media request refused
  on one video 12 of 12 times, and the same URLs playing a minute later; a
  benchmark of 53 request shapes over Wi-Fi and LTE then showed the refusal
  tracks the answer's pre-roll ad and found a second source (TV_TIZEN signed
  out) that serves those videos with no wait. Details:
  `~/projects/newtube-launch/netbench/` on the maintainer's machine.
- Not tested: a real Samsung or Android 7 device.
