# NewTube 1.13.0 — Faemino y Cansado Edition

Release date: **2026-09-30**. Android version code: **11300**. Package:
`io.github.aleixrodriala.arc`. Android 7/API 24 or later; target/compile API 37.

The Spanish announcement is a fictional, unofficial homage to Faemino y Cansado
and their deadpan back-and-forth. It is not an endorsement and quotes no real
routine.

## Why this release

1.12.0 shipped comments as a read-only panel. The owner called writing comments
"a main feature" the same evening, and the only Reddit user who asked for it
(r/AfterVanced, "Ability to respond") said they would daily-drive NewTube once
it landed. The chapters list (#13) and a player that feels like YouTube's, both
held back from 1.12.0, were finished the same day. The owner's call: ship all
three together.

## Validation

- Unit tests on the release commit: phone suite (`testStmobileDebugUnitTest`)
  and `common` (`testDebugUnitTest`) with no failures; the 13 new MediaServiceCore
  comment tests pass offline. `CommentsApiTest.testToggleLike` and `PanelApiTest`
  need a live signed-in session and are not run.
- Writing comments, on YouTube itself, from the test account only (never the
  owner's), with the owner's OK each time:
  - Spike (a temporary probe, never committed): `create_comment` answered
    "Comment added" and `create_comment_reply` with params
    `{2: videoId, 4: parentId, 5: {1: 0}, 10: 7}` answered "Reply added"; the
    delete action `{1: 6, 2: 2, 3: commentId, 5: videoId}` answered "Comment
    deleted". A signed-out TVHTML5 read showed each item before its delete and
    not after.
  - Through the new UI on the Xiaomi Mi 8 (Android 15), `.check` build of
    `f0455768`: posted a comment (top of the list, ⋮ only on it), replied via
    Reply ("1 reply"), force-stopped and reopened (Newest still showed ⋮ on it:
    the handle match works across sessions), deleted the reply, then the
    comment. Signed-out yt-dlp read of the 40 newest comments: none left.
  - Emulator (API 35, signed out, light and dark): composer above the keyboard,
    Reply prefill, sign-in prompts, delete confirmation, Try again; no write
    requests sent.
  - Codex (gpt-6.1-sol) review: 3 P1 and 8 P2 findings, all fixed but one (below).
- Chapters, seek bar, hold for 2x: emulator checks per commit, Codex reviews of
  the seek bar and of hold for 2x with their findings fixed, and the owner's own
  use of release builds on the Mi 8 (the seek bar's touch band came from his
  report); the Mi 8 has had the merged tree's build since 21:10.
- Not tested: a real Samsung or Android 7 device, writing comments on
  Android 16+, a brand-account channel (YouTube has refused comments from brand
  accounts to other clients).

## Known issues

- A comment posted while the panel's first page is still loading, when that
  load then fails, shows only after Try again (the "Comment posted" message
  still confirms it).
- Search with the keyboard open and a mini player docked leaves spare space at
  the bottom.
- Light theme on Android 11 and older: the launch splash follows the system
  theme when the app's choice is the opposite one.
