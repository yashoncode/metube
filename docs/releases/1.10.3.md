## Why this release

The launch on 28 September brought two things to fix before wider posts. The
first is a promise: the in-app copy and one default had to match what the public
pages now say. The cast screens still said "ad-free", and Return YouTube Dislike
was on by default although it tells a third party every video you open. The
second is trust in the binaries: SmartTube's own build machine was compromised
in December 2025, and NewTube's releases were also built on one person's
computer. Issue #2 added a settings bug: every tick scrolled a long page back to
its top.

## Validation and limitations

- Unit tests on the release tree: **633 in `smarttubetv`** (1 opt-in benchmark
  skipped) and **258 in `common`** passed.
- Cross-model review (Codex `gpt-6-sol`, adversarial) of the cast strings, the
  dislike opt-in, the release workflow and both MediaServiceCore commits. Four
  findings, all fixed: a manual workflow run could build another ref with the
  release secrets and attest the wrong commit, and a tag push and a manual run
  used different concurrency groups (fixed by building only the run's own ref);
  switching dislike counts off left the count on the open video.
- Android 15 emulator without Google apps (AOSP, x86_64, debug build): signed-out
  Home, playback, background play with the media notification, a sign-in code
  issued, Google's device page opened in the system browser with the code
  filled in (sign-in not completed). Dislike counts off: 8.3M likes and no
  dislike number; on: 353.9K dislikes. Settings: the Dislike counts row stayed
  at the same y across two toggles; SponsorBlock scrolled → Off-topic → back
  returned the same rows at the same y. After the MediaServiceCore commits:
  playback, and `PoTokenWebView` initialised with no error.
- The first CI-built APK set (1.10.2 code, commit `65161161`): all four signed
  with the release certificate; `gh attestation verify` passes and names
  `release.yml` on a GitHub-hosted runner at that commit; the arm64 APK played
  past 1:45 under ARM translation on an Android 36.1 emulator.
- Size: releases up to 1.10.2 were built on a machine without the NDK, so
  `libj2v8.so` shipped unstripped (32 MB in arm64, "with debug_info"). The CI
  runner installs NDK 21.0.6113669 as `ndkVersion` asks, so the libraries are
  stripped and the arm64 APK is about 20 MB smaller.
- Not tested: a real Android 7 device (the `d9ba6d3a` crash is upstream's
  report), real Huawei/Fire devices, Samsung One UI.
- Still open: the "Unknown source error" report on a Redmi Note 14 4G, and the
  second half of #2 (splitting the long settings pages into sub-pages).
